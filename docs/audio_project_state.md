# Audio Codec Extension — Project State

*Last updated: 2026-04-14 · Branch: `feat/paradigm-audio-codecs`*

---

## 1. Scientific motivation

The SWP project trains LSTM encoder-decoder networks to perform **auditory word repetition**
(hear a word as phonemes → repeat it), and probes them with tests inspired by human behavioral
studies. The paper is:

> **"A Neural Model for Word Repetition"**
> arXiv: [2506.13450](https://arxiv.org/abs/2506.13450)

The core finding is that neural models can reproduce several human-like behavioral effects
(lexicality, word length, frequency, morphological complexity), while diverging in other
important ways — pointing to both the promise and the limits of biologically grounded language
models.

### Why audio codecs?

The SWP paper uses a purely phonemic representation (grapheme → IPA → embedding). The audio
extension asks a complementary question:

> **When a state-of-the-art neural audio codec hears and reconstructs a word, do its internal
> representations encode the same linguistic factors (lexicality, length, frequency, morphology)
> that drive human and SWP-model behavior?**

The codec is used as a **passthrough** (no training, weights frozen) applied to actual speech
recordings of the paradigm stimuli. We compare:
- How well the codec reconstructs each word (signal metrics)
- Whether latent activations at different codec layers encode the SWP behavioral factors
- Whether the pattern is the same across codec architectures (EnCodec vs DAC)

This is a direct bridge between the symbolic SWP model and raw acoustic processing.

## 2. Dataset: the lab paradigm stimulus set

### What it is

English words and pseudowords from the lab paradigm (`en_paradigm.csv`), recorded by a single
speaker. 180 items total: words and nonwords balanced across four orthogonal factors:

| Factor | Values | Applies to |
|--------|--------|-----------|
| `lexicality` | `word` / `nonword` | all items |
| `length_bin` | `long` / `short` | all items |
| `frequency_bin` | `high` / `low` | words only (NA for nonwords) |
| `morphology` | `complex` / `simple` | all items |

These are the **same factors** tested in the SWP behavioral analyses (Figure 2 of the paper).
This is what makes the comparison meaningful.

### Location

Raw files (not versioned):
```
data/external/paradigm/raw/metadata.csv      # item metadata + condition codes
data/external/paradigm/raw/wav/              # WAV files per item
```

Processed CSV (generated by `setup_paradigm.py`):
```
data/external/paradigm/processed/subset_male.csv   # 180 items, male speaker
```

The processed CSV includes normalized columns:
`item_id`, `wav_path`, `original_sample_rate`, `duration_s`, `speaker`,
`condition`, `lexicality`, `length_bin`, `morphology`, `frequency_bin`.

## 4. End-to-end pipeline

```
Step 0  setup_paradigm.py      Raw WAVs + metadata.csv → processed/subset_male.csv
           ↓
Step 1  extract.py             Codec forward pass → metrics.csv + activations/*.pt
           ↓
Step 2  analysis.py            metrics.csv → OLS regressions + bar plots (signal level)
           ↓
Step 3  activation_analysis.py activations/*.pt → OLS regressions + plots (latent level)
```

### Caching / idempotence

Each extraction run is identified by a **paramhash**: SHA-256 (8 hex chars) of the sorted
JSON of `{model_name, model_kwargs, dataset_path, layers, sample_rate}`. This means:
- Identical runs are skipped automatically unless `--regenerate` is passed
- Changing any parameter creates a new directory, never overwrites old results
- `manifest.json` inside each run directory stores the parameters in plain text

### Output layout

```
reproduce/data/audio/
├── encodec__7f7d3b97/
│   ├── manifest.json
│   ├── metrics.csv              # item_id, mel_distance, si_sdr
│   └── activations/{item_id}__{layer}.pt   # 180 items × 3 layers = 540 files
└── dac__f104bbdd/
    ├── manifest.json
    ├── metrics.csv
    └── activations/{item_id}__{layer}.pt
```

At the current stage of this branch, the paradigm pipeline stores:
- reconstruction metrics
- per-item per-layer activation tensors

It does **not** currently store reconstructed audio files as part of the standard run outputs.
If needed later, audio saving can be added explicitly as an option in the extraction pipeline.

## 5. Models integrated

### EnCodec (`encodec`)

- **Source**: HuggingFace `facebook/encodec_24khz`
- **Architecture**: Convolutional encoder → residual vector quantizer (RVQ) → convolutional decoder
- **Sample rate**: 24 000 Hz
- **Key kwarg**: `bandwidth` in kbps (valid: 1.5, 3.0, **6.0**, 12.0, 24.0)
- **Weights**: downloaded automatically, cached in `~/.cache/huggingface/`

### DAC (`dac`)

- **Source**: `descript-audio-codec` native package (not HuggingFace)
- **Architecture**: Convolutional encoder → improved RVQ → convolutional decoder
- **Sample rates**: 16 kHz / **24 kHz** / 44.1 kHz (selected via `model_type`)
- **Key kwarg**: `model_type` (default: `"24khz"`)
- **Weights**: downloaded automatically, cached in `~/.cache/descript/dac/`
- **Why native package, not HF**: cleaner API (`encode()`/`decode()` explicit), no second HF
  dependency, and the native package was already the standard for DAC

### Shared API contract

Both models implement the `AudioModel` Protocol (`swp/audio/models/base.py`):

```python
model.reconstruct(waveform)              # → ReconstructionResult
model.extract_activations(waveform, layers)  # → dict[layer_name → Tensor]
model.available_layers()                 # → ["encoder_out", "decoder_in", "decoder_out"]
model.name / model.sample_rate
```

### Stable layer names (both models)

| Layer | Hook type | Shape | Meaning |
|-------|-----------|-------|---------|
| `encoder_out` | forward post | `[D, T_enc]` | Encoder output, before quantizer |
| `decoder_in` | forward **pre** | `[D, T_enc]` | Quantizer output, input to decoder |
| `decoder_out` | forward post | `[1, T_audio]` | Reconstructed waveform |

`D` = 128 (EnCodec) or 1024 (DAC). `T_enc` ≈ `T_audio / 320` at 24 kHz.

The `decoder_in` layer requires a **forward pre-hook** (not a standard forward hook), because
we want to see what comes out of the quantizer before the decoder processes it.
This is why the `HookManager` was built with explicit pre-hook support.

### Activation extraction: comparison with base SWP

| Aspect | Base SWP (LSTM) | Audio codecs (this branch) |
|--------|----------------|---------------------------|
| Hook system | Simple per-hook function, buffer dict | `HookManager` class, multiple hooks |
| Pre-hooks | No | Yes (`decoder_in`) |
| Extractor functions | No | Yes (unwrap HF/DAC-specific outputs) |
| Output format | numpy array, projected to 2D | PyTorch tensor `[C, T]`, full temporal structure |
| Storage | CSV with trajectory column | `.pt` file per item per layer |
| Features computed | Trajectory embedding (MDS/PCA) + permutation importance | Norms, trajectory length, step distance |

## 6. Key methodological choices

### Why `encode()`/`decode()` and not `model.forward()`

DAC's `forward()` adds RVQ training loss terms. Using `encode()` + `decode()` gives a clean
inference path matching what the paper's codec literature measures.

### Why mel distance and SI-SDR

Two complementary signal metrics are used:

- **Mel distance** (mean absolute log-mel spectrogram distance) is the main perceptual/spectral
  metric. It is less sensitive than waveform-level metrics to small phase shifts or sample-level
  misalignment, and is therefore the most useful metric for comparing reconstruction quality
  across codec architectures.
- **SI-SDR** (Scale-Invariant SDR) measures waveform-level fidelity after optimal rescaling.
  It is much stricter and more sensitive to phase and temporal alignment.

In our current results, DAC achieves much lower mel distance than EnCodec, indicating better
perceptual/spectral reconstruction, while EnCodec achieves much higher SI-SDR, indicating
better waveform-level alignment. For DAC, SI-SDR is still mathematically valid, but it is less
informative as a proxy for perceived quality than mel distance.

### Frame-controlled trajectory analysis (Step 6)

The standard `trajectory_length` feature is confounded with sequence duration: longer words
have more frames → longer trajectories by construction. Three complementary normalizations
were implemented to separate duration effects from genuine latent dynamics:
- `trajectory_length_per_frame = trajectory_length / n_frames`
- `mean_step_distance = trajectory_length / (n_frames - 1)` (per-step average)
- OLS model with `n_frames` as covariate: `trajectory_length ~ C(factor) + n_frames`

### `--save-audio` flag

Off by default. When enabled, saves `{item_id}__original.wav` and
`{item_id}__reconstructed.wav` under `{run_dir}/audio/` for perceptual listening comparison
across models.

## 7. Current state of results

### Validated pipeline state

The full pipeline now runs end-to-end for both models on the male-speaker paradigm subset
(180 items):

- **EnCodec full run**: `encodec__7f7d3b97`
- **DAC full run**: `dac__f104bbdd`

For both runs:
- extraction completed successfully
- `metrics.csv` was written
- `manifest.json` was written
- 180 items × 3 layers = 540 `.pt` activation files were generated
- `analysis.py` was run successfully
- `activation_analysis.py` was run successfully

### Reconstruction-level results

The two models show clearly different reconstruction profiles:

- **DAC** achieves much lower `mel_distance` than EnCodec, indicating substantially better
  perceptual/spectral reconstruction quality.
- **EnCodec** achieves much higher `SI-SDR` than DAC, indicating better waveform-level fidelity.

Factor effects at the reconstruction level:
- In both models, **lexicality is weak or absent**
- **Length** is the most robust factor
- Morphology and frequency effects are weaker and less stable

### Activation-level results

The most robust current result is a **latent length effect** across both models:

- It appears in both `encoder_out` and `decoder_in`
- It remains visible after controlling for `n_frames`
- It also remains in duration-normalized features such as:
  - `trajectory_length_per_frame`
  - `mean_step_distance`

By contrast:
- **lexicality effects do not survive frame-controlled analyses**
- morphology and frequency effects are weaker, less consistent, and more model-dependent

### Current scientific interpretation

At this stage, the strongest conclusion is:

> Across two quite different neural audio codecs, the most robust result is a latent length
> effect. By contrast, lexicality does not currently show a robust, frame-controlled
> dissociation.

This suggests that the codecs strongly encode sequential/temporal load, but do not yet provide
clear evidence for a dual-route-like lexical vs non-lexical separation.

## 8. Current limitations

- **Single speaker processed so far**: only the male speaker subset (`subset_male.csv`) has
  been used in the current validated runs.
- **No explicit cross-model comparison script yet**: EnCodec and DAC have both been analyzed,
  but comparison is still done manually across run outputs rather than through a dedicated
  joint analysis script.
- **No PCA / geometry visualization yet**: the full temporal activation tensors are saved and
  summary dynamics features are computed, but no PCA-based visualization of trajectories has
  been implemented yet.
- **No encoding-model format yet**: activations are stored as `.pt` tensors, but they have not
  yet been converted into a unified `(trials, time, neurons)` structure for univariate or
  multivariate encoding analyses.
- **No phoneme-level alignment**: the current analysis remains at the waveform / latent frame
  level and is not aligned to phoneme boundaries.
- **No ablation pipeline yet**: hard and soft ablation studies are planned but not implemented.
- **No new stimuli yet**: current results are based only on the existing English paradigm
  stimuli.

## 10. How to run the full pipeline (quick reference)

```bash
# Step 0: build processed CSV (one-time, if not already done)
python scripts/audio/setup_paradigm.py \
    --metadata data/external/paradigm/raw/metadata.csv \
    --wav-dir   data/external/paradigm/raw/wav \
    --filename-col Audio_Male \
    --output    data/external/paradigm/processed/subset_male.csv

# Sanity checks
python scripts/audio/sanity_check.py --model encodec
python scripts/audio/sanity_check.py --model dac

# Step 1: full extraction runs
python scripts/audio/extract.py \
    --model encodec --model-arg bandwidth=6.0 \
    --dataset data/external/paradigm/processed/subset_male.csv \
    --layers encoder_out decoder_in decoder_out \
    --output reproduce/data/audio/ \
    --regenerate

python scripts/audio/extract.py \
    --model dac --model-arg model_type=24khz \
    --dataset data/external/paradigm/processed/subset_male.csv \
    --layers encoder_out decoder_in decoder_out \
    --output reproduce/data/audio/ \
    --regenerate

# Step 2: signal-level analyses
python reproduce/scripts/audio/analysis.py \
    --results reproduce/data/audio/encodec__7f7d3b97/metrics.csv

python reproduce/scripts/audio/analysis.py \
    --results reproduce/data/audio/dac__f104bbdd/metrics.csv

# Step 3: activation-level analyses
python reproduce/scripts/audio/activation_analysis.py \
    --run reproduce/data/audio/encodec__7f7d3b97/

python reproduce/scripts/audio/activation_analysis.py \
    --run reproduce/data/audio/dac__f104bbdd/
```
